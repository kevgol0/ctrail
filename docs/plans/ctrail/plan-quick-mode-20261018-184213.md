## Concise View

### Decisions (agreed on the ticket, 2026-10-18)

1. `-q/--quick PATTERN`, **repeatable**. Each pattern is a **case-sensitive Java regex**, `find()`
   anywhere in the line.
2. **Highlight, never filter.** Every line is shown; a matching line is coloured **whole**.
3. One colour per pattern, in order; a line matching several takes the **first** `-q`'s colour.
4. Quick mode **ignores `ctrail.xml` entirely** and **ignores every other flag** except `-h` and
   `--version`. Its defaults are fixed and cannot be overridden.
5. History: **last 1000 lines** per file, then follow.

[→ Detailed](#d-decisions)

### Approach — one idea

Quick mode is **a different `CtrailProps`, not a different code path.** When `-q` is seen, the
singleton is replaced by an instance built from compiled defaults — it **never reads the config
file** — with the quick settings and the compiled patterns on it. Every reader, the writer and
the formatter already take their settings from `CtrailProps` at construction (CTRAIL-19), so
config isolation falls out for free: there are no filters, no excludes and no colour pairs to
ignore, because none were loaded.

The only new behaviour is in `LineFormatter`: when the props carry quick patterns, it colours by
regex instead of by keyword.

[→ Detailed](#d-approach)

### Changes

| File | Change |
|---|---|
| `props/QuickPattern.java` | **new** — compiled `Pattern` + its colour + the source text |
| `props/CtrailProps.java` | `installQuickDefaults(...)`: defaults-only instance, never reads the file |
| `unit/LineFormatter.java` | regex colouring when quick patterns are present; first match wins |
| `CtrailEntryPoint.java` | `-q` option; compile patterns; WARN on ignored flags; usage errors → exit 2 |
| `CtrailUsageException.java` | **new** — bad `-q` regex or unparseable arguments → stderr + exit 2 |
| README, CHANGELOG, version files | document quick mode; 1.4.2 → 1.5.0 |

[→ Detailed](#d-changes)

### ⚠️ One change beyond the story

**Any command-line parse error becomes a usage error (stderr, exit 2).** Today a parse error is
logged and the raw arguments are treated as file names, so `ctr -q` with no value would report
"none of the files given could be read: -q". The story requires a proper usage error for that
case, and the clean way is to fix it for every option, not just `-q`. Say so if you want it
limited to `-q`.

[→ Detailed](#d-beyond)

### Tests and verification

~20 new JUnit 4 tests across props, formatter and CLI, each red-checked by reverting the line it
covers; full suite green; smoke-tested on the packaged jar against a config that would filter and
recolour.

## Detailed View

<a id="d-decisions"></a>
### Decisions ([↑](#concise-view))

All eight are recorded on CTRAIL-22. The fixed quick defaults:

| Setting | Quick value |
|---|---|
| Lines shown | all — no `-m`, no file filters, no stdin filter, no excludes |
| Matching | case-sensitive regex, `Pattern.compile(p)`, `matcher(line).find()`; `(?i)` available inline |
| Colouring | whole line; pattern *n* gets palette[*n* mod 6]; first matching pattern wins |
| Palette | `RED_BOLD`, `ORANGE` (yellow bold), `CYAN_BOLD`, `GREEN_BOLD`, `PURPLE_BOLD`, `BLUE_BOLD` |
| Unmatched lines | `ConsoleColors.WHITE` |
| History | `setTailLast(1000, LINES)` |
| Filename prefix | on only when more than one file argument |
| Startup banner | on; one quick-mode line, then the usual per-file banner |
| Idle notices | off (`idleNoticeSeconds = 0`) |
| Charset | UTF-8 |
| Everything else | compiled defaults from `CtrailProps` field initialisers |

<a id="d-approach"></a>
### Approach ([↑](#concise-view))

**Why replace the props instead of overriding them.** "Ignore the config" by overriding means
finding and neutralising every setting the config can affect — filters, excludes, stdin filter,
colour pairs, file colours, case sensitivity, `matchFirstWord`, charset — and the next config key
anyone adds becomes a leak. An instance that never read the file cannot leak.

**Why this is safe now.** Construction order is: `loadProps()` → `loadArgsAndOverrides()` →
`initConsoleWriterThread()` → `initInputReaderThread()`. The quick instance is installed during
argument parsing, before the writer, readers and formatter are built, and since CTRAIL-19 those
capture `CtrailProps` once at construction. Nothing reads props after that.

**The one caveat.** `loadProps()` runs before argument parsing, so the config file is still
**read** (and its parse warnings, e.g. deprecated keys, are still logged) before being discarded.
Moving `-q` detection ahead of `loadProps()` would avoid even that, but means parsing arguments
twice. I propose to accept it: the file is read, never used. Its WARNs being printed in quick
mode would be misleading, so `loadProps()` is moved after a cheap pre-scan for `-q`/`--quick`
**only if** a test shows those WARNs appearing. Decided during build, reported either way.

<a id="d-changes"></a>
### Changes ([↑](#concise-view))

#### `props/QuickPattern.java` — new

```java
@Value
public class QuickPattern
{
    String  source;   // as typed, for the banner
    Pattern pattern;  // compiled once
    String  color;    // ANSI code from the palette
}
```

#### `props/CtrailProps.java` — edit

- New field `@Getter private List<QuickPattern> _quickPatterns = List.of()` (empty = normal mode).
- New `public static synchronized CtrailProps installQuickDefaults(List<QuickPattern> patterns_, boolean multipleFiles_)`:
  builds a defaults-only instance via a new private no-file constructor, applies the quick
  table above, sets `_instance` and pins `_instanceCfgOverride` to the current property value so
  `getInstance()` keeps returning it.
- The private no-file constructor initialises the collections and sets `_defaultFgColor` to
  `ConsoleColors.WHITE` — the field initialiser holds the **name** `"white"`, not an ANSI code,
  and only the file-reading path converts it today.
- `public boolean isQuickMode()` → `!_quickPatterns.isEmpty()`.

#### `unit/LineFormatter.java` — edit

- Capture `_quickPatterns` at construction like every other setting.
- In `format()`, after the notice check: if quick mode, colour = first pattern whose
  `matcher(line).find()` is true, else default; skip the keyword loop entirely. Extracted into
  `private String quickColorFor(String line_)` to keep `format()` readable.
- Filename prefix takes the same colour as the line, as today.

#### `CtrailEntryPoint.java` — edit

- `-q/--quick` option, `hasArg()`, repeatable (`getOptionValues("q")`).
- `applyQuickMode(String[] patterns_, CommandLine line_, int fileCount_)`:
  1. compile each pattern; `PatternSyntaxException` → `CtrailUsageException` naming the pattern
     and the regex error;
  2. build `QuickPattern`s with palette colours;
  3. WARN once listing any of `-m -n -c -e -f -v` that were given;
  4. `CtrailProps.installQuickDefaults(...)`;
  5. queue the banner `ctrail: quick mode, highlighting "A", "B" - config and other flags ignored`.
- In quick mode the other option handlers are skipped (`-h`/`--version` are handled first, as
  they exit).
- `_matchpattern` stays null in quick mode, so the readers' `-m` filter is off.
- `main()` catches `CtrailUsageException` alongside `NoReadableInputException`: message to stderr,
  exit 2.

#### `CtrailUsageException.java` — new

Same shape as `NoReadableInputException`. Considered reusing that class; rejected, because "the
files you named are unreadable" and "your arguments are malformed" are different messages to the
user and different cases in tests.

<a id="d-beyond"></a>
### Parse errors become usage errors ([↑](#concise-view))

`loadArgsAndOverrides` currently does:

```java
catch (final ParseException ex_)
{
    _logger.error(ex_.toString());
}
return args_;   // raw args, options included, treated as file names
```

Proposed: throw `CtrailUsageException("<parser message>; see ctr -h")`. Affects `ctr -q` with no
value, `ctr -n` with no value, and unknown options such as `ctr --bogus`. All three already exit
2 since 1.3.1 (via the unreadable-files path), just with a misleading message, so the exit code
does not change — only the message does.

### Build / verify

1. `mvn clean test` — full suite green (random class order, as configured).
2. Red-check each new test.
3. `mvn clean package`, then smoke with `-DCTRAIL_CFG=<isolation fixture>`:
   - `ctr -q ERROR app.log` → all lines, `ERROR` lines red, a `WARN` line **not** yellow;
   - `ctr -q ERROR -q 'time(d)?out' -n 5 app.log` → WARN naming `-n`, two colours;
   - `ctr -q '['` → stderr message, exit 2;
   - `printf 'a\nXX b\n' | ctr -q XX` → both lines, second coloured.
4. ✅ / ❌ verdict in the modifications log.

### Out of scope

- Highlighting only the matched text (decided: whole line).
- Overriding quick defaults (decided: fixed).
- A config-file equivalent of quick mode (`<quick>` in `ctrail.xml`).
- The pending config-loading bug (one bad value aborts the rest of `ctrail.xml`) — quick mode
  ignores the file, so it is unaffected, but the bug remains for normal mode.
